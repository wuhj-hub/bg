# 产物副本约定（仓库内规则）

> 建立 2026-10-14 ｜ 关联：CHANGELOG v2.9、`quant_scripts/report_io.py`、`quant_scripts/artifact_audit.py`
> 完整版见知识库「报告 → 指标存档」《产物副本口径与新鲜度约定.md》

## 背景
同名「latest」产物常在**仓库根**（`X_latest.json`）与 **`outputs/`**（`outputs/X_latest.json`）两处并存。
两处不同步 + 读取方读了旧的一份 = **静默使用陈旧数据**（实例：盘前③.3 板块共振读取了冻结于 2026-08-13 的 `outputs/` 副本）。

## 规则
1. **双副本要么「双提交」，要么「只保留一份」** —— 不得只提交其中一份、另一份留在仓库造成冻结。
2. **读取方存在多副本时必须走 `report_io.load_latest(paths)`**（按 `data_date>bar_date>trade_date>date` 取最新），禁止硬编码路径优先级。
3. **判危险看「生产者作业 vs 消费者作业」**：
   - 跨作业（生产在 A 作业、消费在 B 作业）：`outputs/` 副本一旦掉出提交清单即冻结 → **高危**。
   - 同作业：运行时刚写过 → 相对安全，但仍须遵守规则 1。
4. **新产物优先只放仓库根**（与惯例 `cp outputs/… → 根 → 提交根` 一致）。
5. **存量双提交产物（env/market_width/qiankun/四维共振/sector_component_em/xihu_breadth_history）维持「双提交」**，不强制归并（已在同步，归并有 workflow 改动风险）。

## 守门
- `artifact_audit.py`：
  - `check_dup_freshness()` —— 根 vs `outputs/` 同名产物日期不一致 → `dup_stale`（`--strict` 退出1）；
  - `check_reader_bypass()` —— 消费方对「存在多副本的产物」直接 `open()` 而未走 `report_io.load_latest` → 列出（编写期预警）。
