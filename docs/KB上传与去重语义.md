# KB 上传与「同日去重」语义（upload_ima.py）

> 2026-10-15 建档 · 数据可信度治理 11.4
> 适用：仓库根 `upload_ima.py`（全体系统一上传入口）

## 1. 背景问题

知识库**没有删除 API**，同名文件也**不会覆盖**（服务端自动追加后缀）。早期为避免同名堆积，上传前做「同名跳过」（`IMA_SKIP_DUP=1`，且为内置默认）。

副作用：**同一天内产出的改进版会被先前版本挡住 → KB 静默不更新**。
- 实证：2026-10-15《复盘报告》01:54 定时版先入库，22:00 修复版上传时被同名跳过 → KB 长期停留在旧版，且无任何报错。

## 2. 新语义（v2.32 起）

决策优先级：**显式环境变量 > 文件名自动判定**

| 条件 | 行为 |
|---|---|
| `IMA_OVERWRITE=1` / `IMA_SKIP_DUP=0` | 覆盖（旧版归档 + 新版占正名） |
| `IMA_SKIP_DUP=1` | 同名跳过（防堆积） |
| 未显式指定 + **文件名含日期**（`YYYY-MM-DD` 或 `YYYYMMDD`） | **同日覆盖** |
| 未显式指定 + 文件名不含日期 | 同名跳过 |

**「同日覆盖」实现**（因无删除 API，只能改名）：
1. 列举目标文件夹已有条目，命中同名者取其 `media_id`
2. `rename_knowledge` 把旧条目改名为 `<正名>_prev_<HHMMSS>`（归档，仍可检索）
3. 正常 `create_media → cos_upload → add_knowledge`，新版本占用**正名**

⇒ **正名恒为最新版**，历史版本以 `_prev_HHMMSS` 留存。

## 3. 为何按「文件名含日期」自动判定

- 全体系上传点约 25 处，逐处加 env 易漏易漂；改为在上传入口统一判定，**一处生效**
- 日期化文件名 = 日报类产物（复盘/盘前/竞价/股池跟踪/胜率总览…）→ 语义就是「当天唯一最新版」
- 非日期名 = `*_latest` 或稳定口径文档（如《入牛广度阈值与行业口径说明.md》）→ 应防堆积，保持跳过
- 上传时会打印 `[MODE] 同日覆盖|同名跳过 | 文件名含/不含日期 …`，便于日志追溯

## 4. 运维要点

- 同一天多次运行 → 会连续归档（`_prev_0900`、`_prev_1600`…），历史不丢；归档件可按需人工清理
- 归档改名失败（网络/鉴权）→ 仅 `WARN`，继续上传（可能产生同名副本，宁可重复不丢数据）
- 需要「强制重传但保留旧名」：`IMA_SKIP_DUP=0`（不归档，直接新增一件同名）
- 需要「指定历史日期的报告重新入库」：走覆盖路径即可（归档旧件 → 新件占正名）
