## 二、迁移方式（包裹式·低风险）

对「脚本自建 `WESTOCK=[npx...]` + `cli()/run()`」的脚本，把取数函数**委托**给 `fetch.raw`，
**解析逻辑保持不变**：

```python
def cli(args, timeout=90):
    out = _fetch_raw(args, timeout)      # from fetch import raw as _fraw
    if out is None:                      # fetch 层不可用 → 回退本地 npx
        ...本地 subprocess.run(WESTOCK + args)...
    return out if _valid(out) else None
```

收益：免 npx（≈3.5s→0.7s/次）、统一重试退避、统一超时。

## 二·补 · 阶段 4：新增外部源适配器（2026-10-23）

阶段 3 解决的是「把已存在的取数收口」，阶段 4 起补**体系里原本没有的数据源**。
首批两个适配器为「抱团瓦解监控」（`quant_scripts/crowding_watch.py`）服务：

| API | 数据源 | 关键字段 | 用途 |
|---|---|---|---|
| `ext_em_margin(codes, date)` | 东财 datacenter `RPTA_WEB_RZRQ_GGMX` | `margin_bal` 融资余额、`bal_ratio` 占流通市值%、`net/net5/net10` 净买入 | 拥挤度绝对水平 + 变化方向 |
| `ext_em_report(codes, begin, end)` | 东财 `reportapi/report/list` | `rating_change`(0调高/1调低/2首次/3维持)、`eps_this/eps_next` | 边际盈利上修广度 + 卖方关注度 |

实测要点（2026-10-23，写进适配器 docstring，避免下次踩）：
- 两融报表名是 **`RPTA_WEB_`** 前缀（不是 `RPT_`，写 `RPT_MARGIN_*` 报「报表配置不存在」）；
  `filter=(SCODE in ("300308","300502"))` 批量语法可用；
- `ratingChange` 语义按东财页面 `data-bdcode` 对齐：0=调高 1=调低 2=首次 3=维持；
  **调低条数极少**（券商少报下调，近 600 篇里仅 1 条）→ 只作辅助判据；
- 研报 `pageSize` 上限实测 100（传 200 只回 100）；全市场 180 日约 5800 篇 / 58 页；
- 两融 T+1 披露，最新一条通常比今天早 1 个交易日。

产物：`quant_scripts/crowding_watch.py`（三块指标 + `outputs/拥挤度监控_{date}.md|.json`）。
